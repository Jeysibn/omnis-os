# Threat model, invariants, browser boundary

Threat actors include untrusted WSL users/processes, other containers, stale/replayed callers, compromised API/bootstrap, delayed schedulers, and accidental operator cleanup. Threats include authorization misuse, revocation races, session invalidation, fixture substitution, PID reuse, same-UID peer impersonation, descriptor transfer, socket replacement, controller/supervisor/manager death, late startup, escape, daemon outage, residue, shared writable paths and privilege escalation.

Controls: signed exact-scope owner authorization; issuer live-session lookup; linearizable revocation/consumption ledger; Stage 1-owned read-only reservation validation; mutual IPC identity checks; one-use permit and no retry; kernel-enforced first-application-instruction deadline fence; frozen pre-exec cgroup; independent finalizer; persistent startup deny interlock; exact resource IDs; separate cleanup authorization. Any unverified guarantee blocks. Trusted root/kernel/system manager and issuer key custody are assumptions. No real-provider execution is allowed.

Before physical release: exact live Stage 1 session/reservation; owner authorization for exact operation/fixture; current active owner session; unexpired single-use authorization and no prior revocation; same boot; original Stage 1 deadline; Stage 1 live-session ordering established under an approved lease contract; one-use durable consume; validated peer and pinned executable/unit identities; fixture generation/config match; pre-exec frozen cgroup and finalizer armed; observation ready; atomic fence proven. Stage 1 reservation alone is not release authority. Lost acknowledgment is never retried. Quarantine requires positive process termination and exposure assessment. Cleanup is exact-ID and separately authorized.

Deployment preference remains Windows browser → localhost port → Omnis OS in Docker on existing WSL2 Ubuntu; custom domain unnecessary. WSL-local processes, sibling containers and LAN remain untrusted. Localhost/source IP, Host/Origin, authentication, and CSRF are distinct signals; none alone proves Windows-host provenance. Existing owner authentication, active session and CSRF protections remain required. Phase A designs A/B govern origin policy and observation; E governs isolated Windows browser.

Browser design: separate installed executable and private experiment profile; create suspended, assign nonbreakaway Windows Job Object with KILL_ON_JOB_CLOSE, then resume; independent owner of job handle/deadline, positive empty-job check. Fixture-scoped leaf/SPKI exception only; no persistent trust-store changes and no global ignore-certificate-errors. Windows helper and certificate method remain unimplemented and need explicit owner decision and target evidence. No network, browser or certificate actions here.


V3 closure boundary: the V2 liveness snapshot is insufficient to authorize consumption. Stage 1 controller death between snapshot and Stage 2 commit remains blocking. The kernel deadline fence is also not established. Both are explicit unresolved safety properties, not accepted residual risks.
