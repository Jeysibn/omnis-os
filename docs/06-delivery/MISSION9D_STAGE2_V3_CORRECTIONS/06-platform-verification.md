# Platform verification and per-test authorization matrix

This is an executable-test specification, not permission to run tests. Each target case requires its own written owner grant naming host, fixture, case IDs, privilege, window, data/evidence bounds, expected side effects and cleanup authority. Generic approval of platform validation is insufficient. Tests use disposable fixtures only; no provider activity. A test is **PASS** only when every listed evidence item is captured and all criteria hold; any failed criterion is **FAIL**; missing evidence, test interruption or environment drift is **INCONCLUSIVE**, which blocks release. Cleanup occurs only under the same explicit test grant and only for exact recorded IDs; otherwise leave a blocking recovery record.

## Test scope and ordering

Source-only S1 and synthetic M1–M3 can establish schema and logic properties but cannot establish kernel scheduling, cgroup placement, system-manager survival, filesystem durability, Windows packet translation, Job Object semantics, or ingress provenance. H1–H10 each require separate owner authorization as shown. H8 LAN, H3 power-loss, H6 daemon disruption and H7 WSL restart need specific disruptive scope; they are not implied by ordinary target validation. H9 must pass before enabling IPC. H5 and H4 must pass before any release design can advance. H1/H2/H3 must establish Stage1 clock and ledger storage. H8 remains blocked by ADR-0012 provenance. H10 is only needed for browser path and does not establish ingress provenance.
