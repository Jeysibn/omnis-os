## Status definitions

- **DESIGN SPECIFIED:** a testable control/procedure is described; no implementation or test pass is implied.
- **UNPROVEN:** the current evidence does not establish the requirement.
- **REQUIRES EXPERIMENT:** only a separately authorized runtime test can resolve the named compatibility question.
- **INCOMPATIBLE:** a candidate cannot meet the requirement as proposed; a specific replacement is needed (for example AuthZ plugin as the sole Docker API enforcement).
- **BLOCKED:** a required security invariant has no credible enforcement path or a stop condition was met. If the policy gateway cannot hide the raw Engine socket, or egress relies only on launcher-supplied options, mark the Runtime Engine architecture BLOCKED.

## Static configuration gate

Any later proposal must reject: rootful socket paths; raw Runtime Engine socket in launcher/Core; `privileged: true`; `network_mode: host`; wildcard/LAN gateway binds; API/worker/database host ports; arbitrary image/command/mount input; WSL/Windows path mounts; secret `env_file`/build args; insecure-origin flags; wildcard Origin; forwarded-header trust without a specifically approved proxy boundary; direct runtime egress routes; plugin/gateway policy writable by launcher; and CI triggers without separate authorization. Static configuration cannot establish effective kernel isolation, API completeness, WSL forwarding, firewall behavior, quotas, or recovery.
