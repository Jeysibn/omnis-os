## Verified backend interface for Claude #2

Use the existing contract schemas as the source of truth; do not add UI-owned interpretations of backend status or provenance.

### Ordinary task and run lifecycle

- `TaskSchema` carries `id`, `title`, `detail`, `status`, `createdAt`, optional `projectId` and `associationRevision`, `agentId`, `profileVersion`, `runtimeId`, `assignmentRevision`, and nullable `resultAcceptance`. The execution-assignment fields (`agentId`, `profileVersion`, and `runtimeId`) are either all null (unassigned) or a complete assignment with `runtimeId: "mock"`.
- Task states are `open`, `in_progress`, `in_review`, and `completed`. Owner acceptance is a separate, explicit result review; a completed Run does not itself complete/accept the Task.
- `RunSchema` carries `id`, `taskId`, `taskTitle`, nullable/optional `authorizationId`, `status`, `runtimeKind: "mock"`, `synthetic: true`, unknown-only `usage`, `createdAt`, and `updatedAt`.
- Run states are `queued`, `running`, `stopping`, `completed`, `cancelled`, `failed`, `interrupted`, and `unknown`. `stopping` is a request awaiting evidence; `unknown` is unresolved. Do not render either as terminal success or confirmed cancellation.
- `RunEventSchema` carries `id`, `runId`, positive `sequence`, `at`, `type`, `source: "mock"`, `synthetic: true`, and `message`. The event type `run.provider_submission_requested` is a lifecycle label in this mock contract; it is not evidence of provider activity.
- Ordinary Run usage is always unknown: token and cost values are `null`, never zero.

### Relevant endpoints and response behavior

- `POST /api/v1/runs`: owner and mutation-protected mock admission; requires a valid `CreateRunSchema` body and `Idempotency-Key`. The route returns 201 when the returned Run is `queued`, otherwise 200; status is selected from the returned Run state, not from whether admission was new or idempotent. Disabled mode or unavailable authorization returns a truthful 503.
- `GET /api/v1/runs`: owner-authenticated Run list.
- `GET /api/v1/runs/:runId`: owner-authenticated Run projection.
- `GET /api/v1/runs/:runId/events`: owner-authenticated SSE. `Last-Event-ID` is a nonnegative safe-integer sequence. The API validates each event and run binding, sends ordered SSE `id`, `event`, `data`, and replays persisted events after reconnect. Current deployment contract is one API replica.
- `POST /api/v1/runs/:runId/stop`: owner and mutation-protected stop request. A request is not itself a cancellation receipt; show the persisted Run status and events.
- `POST /api/v1/tasks/:taskId/accept-result`: owner-reviewed acceptance for an exact completed Run, with CSRF and idempotency protection. It records the acceptance receipt and does not authorize execution.

The test-only synthetic connector endpoints are not product APIs and must not be enabled by frontend controls. They do not expose real provider execution, real provenance, or real billing evidence.
