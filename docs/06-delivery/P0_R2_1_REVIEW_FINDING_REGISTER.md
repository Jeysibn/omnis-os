## Design corrections, implementation blockers, and owner decisions

**Design corrections in this remediation:** one host-service topology; Worker peer identity; per-step ticket schema and request flow; exact payload binding; revocation/lease/dispatch outcomes; independent stop-only authority; explicit rollback options; terminator identity and OPEN mapping gap; non-IP egress evidence requirements; corrected A–E ordering.

**Unimplemented controls:** Gateway/Authorizer enforcement; durable ledger/journal/anchor; stop-only capability and terminator; trusted per-run cgroup registration; external network policy; dual rootless daemons; effective quotas; startup fence; WSL service/socket model. No control is operationally verified by these docs.

**Owner decisions still required:** decide whether the Docker-only target permits the proposed host control services; select the authenticated Core API→Authorizer owner revoke/cancel channel and credential custody; choose journal-anchor Option A or explicitly accept Option B risk; authorize exact signer/key custody; accept Core DB administrator and Runtime daemon TCB or require stronger boundaries; approve root/systemd, identities, Gateway update authority and stop authority; select egress control; decide whole-service fallback versus per-run termination after M-4 design closure; authorize named disposable VM, then separately WSL; preserve ADR-0012 Candidate E unless locality policy is explicitly changed.
