## Owner decisions and implementation dependencies

1. Accept or reject host root/systemd and the owner-approved host provisioner as part of the future trust base; nominate the signing key, package verification and update authority.
2. Explicitly accept or reject the Runtime Engine daemon/UID as a TCB authority with full control over its own Engine. If daemon-compromise containment is required, reject this topology and require stronger isolation.
3. Approve or reject the dedicated launcher/gateway/runtime-engine identities, non-overlapping UID maps, socket groups and Core Engine impersonation boundary.
4. Select or reject the egress enforcement candidate(s) after design review; neither nftables nor systemd cgroup filtering is asserted to work in the target.
5. Approve a named disposable Linux VM with guest-root permission, private no-uplink networking, resource envelope, evidence retention, system-manager/cgroup termination authority, and named hypervisor destroy operator. Hypervisor destruction is final environment cleanup only, not per-run termination proof.
6. Separately authorize a disposable WSL environment after VM results, including the exact NAT/mirrored host configuration and whether a distinct disposable Windows VM is required. No active-host or global setting changes are authorized here.
7. Codex #1 owns the protocol/backend follow-ups in Claude F-13/F-14 and the current-main Mission Lane lock-timeout investigation. This document PR does not change those implementations.
