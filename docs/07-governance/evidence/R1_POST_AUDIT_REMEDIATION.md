- **Data:** synthetic test fixtures only; no provider inference or provider credentials used.

## Executive result

The cross-scope workspace deletion and SSE replay/live race were confirmed and fixed. Anonymous session storage is bounded and routes that do not need an anonymous session no longer create one. Authentication now has per-client exponential backoff and a global cap on concurrent password derivations. Sandbox negative assertions inspect Docker configuration and mount namespace, and controlled fixtures prove that an extra bind mount or synthetic credential causes failure. Omnis-owned authorization is checked at mock task admission and again before execution claim. Database transition methods now fence by both lease owner and `execution_generation`. An ordered, checksum-tracked migration runner and a safe backup snapshot policy were added.

Local remediation tests, frozen installation, formatting, ESLint, strict TypeScript checks, and production build pass. PostgreSQL integration and actual Docker namespace checks could not run: `OMNIS_TEST_DATABASE_URL` is not configured, and this shell cannot access the Docker socket. Browser, backup/restore, worker restart, and GitHub Actions verification were not run on this branch. **The remediation milestone is not considered passed locally until those infrastructure checks are run.** No real AI runtime is authorized or enabled.

## Implementation details

- Workspace directories now use `<base>/<scope-id>/<private-temp-dir>`. Container cleanup remains label-filtered by the same scope and still consults PostgreSQL active leases.
- Worker SSE uses a serialized database drain loop. Database event rows remain the sole event authority; no second event store was introduced.
- `LocalSessionStore` avoids creation on protected routes and enforces expiry cleanup and a configured maximum of 1,024 entries. Capacity pressure evicts anonymous entries before authenticated owner sessions.
- `AuthThrottle` applies a threshold of five failures per socket client, exponential blocks capped at five minutes, at most 2,048 client entries, and four concurrent password verifications.
- Runtime authorization is defined in `packages/policy`; the worker's only built-in authorization is a local mock-only owner grant. PostgreSQL `runtime_kind = 'mock'` and `synthetic IS TRUE` constraints are unchanged.
- Migration checksums were added to the migration ledger while preserving existing rows. Migration SQL remains in ordered files under `packages/db/migrations`.
- Lease owner and generation checks were added to all worker-owned run transitions. Queue terminal reconciliation remains separate because it is not an execution-worker finalization.
- Backup creation now refuses snapshots incompatible with the existing safe-restore rule.
- ADR-0009 documents future connector, authorization, tool, workspace, and audit boundaries. Provider credentials must stay in a trusted connector/broker and never enter tool sandboxes.

## Remaining risks and unverified controls

1. **Database roles:** worker, migrations, pg-boss, and backup/restore currently share the `omnis` database credential. Split owner/admin, migration, and runtime roles, then verify exact pg-boss privileges using disposable PostgreSQL.
2. **Migration runtime:** validate fresh install, upgrade from `0001_initial`, repeat application, checksum drift rejection, and preservation of task/run/event data against disposable PostgreSQL.
3. **Lease runtime:** execute the controlled stale-worker integration scenario against PostgreSQL and verify stale terminal transitions are rejected.
4. **Docker runtime:** run all actual sandbox tests on the approved local daemon; verify the strict mountinfo allowlist against the current Docker/kernel pseudo-filesystems. The host uses rootful Docker and the worker UID, with no demonstrated disk quota. This is not production-grade arbitrary-code isolation.
5. **Canary scope:** run an end-to-end synthetic canary through sandbox environment, files, stdout/stderr, API/SSE, database records, and logs. Never use real credentials.
6. **Worker supervision:** the worker may exit during PostgreSQL outages and needs an approved external restart supervisor. Abrupt termination may leave temporary Docker CLI directories; safe startup cleanup and crash recovery need a dedicated test.
7. **Backup operations:** archive hash manifests do not authenticate backups and scripts do not encrypt them. Define encryption, separate key storage, off-host retention, and verify restored ID sequence state.
8. **API protections:** add bounded pagination/query limits and SSE subscriber/backpressure limits; review HTTPS cookies, host allowlisting, and actor/audit attribution before any network exposure.
9. **Repository controls:** read-only GitHub API review on 2026-11-02 found `main` is not protected and the repository has no rulesets. Actions are enabled with `allowed_actions: all`; secret scanning and push protection are enabled; non-provider pattern scanning and Dependabot security updates are disabled. No settings were changed. The API response does not identify the repository plan or establish plan-level eligibility for each control. No remediation-branch CI ran because the branch was not pushed. No public history was rewritten.
10. **Runtime policy:** durable authorization records, approvals, append-only audit events, provider policy/consent review, network egress controls, connector secret revocation, and per-run authorization are still mandatory. No Hermes, Codex, or Claude inference is enabled.
