## Risks and blockers

1. **Hermes tool scope:** bearer auth protects the API but does not by itself constrain the powerful toolset. Do not call the API with a read-only prompt until a verified tool allowlist and isolated workspace are in force.
2. **Provider-account usage:** existing local sign-in state is personal account material. Do not pass it into a web/API process or a shared service. Any future background run requires the supported provider authorization flow and explicit user consent.
3. **Claude automation policy:** subscription authentication exists on the machine, but this does not approve reuse by an app-owned unattended worker. Keep disabled until reviewed.
4. **Host infrastructure:** The original command shell lacked the current Docker supplementary group. A fresh WSL login showed the already-configured `docker` group and successfully ran Compose; no socket permissions or group membership were changed. Docker group membership is root-equivalent and must remain a deliberate host-owner decision.
5. **Repository baseline:** workspace was empty and had no `.git`, source documentation pack, or existing implementation to preserve. The initial documentation commit records the handoff before code is added.
6. **Dependency reproducibility:** the initial Phase 0 install could not reach the registry. During R1-G1, the registry responded, pnpm 12.16.1 installed dependencies, `pnpm-lock.yaml` was generated, and CI now uses frozen-lockfile installs. Clean-worktree verification is recorded separately below.

## R1-G1 status

The PostgreSQL-backed mock lifecycle is implemented and its local code, database, process-restart, and browser checks passed. Real Hermes/Codex/Claude inference remains disabled. R1-G1 does not authorize provider use or claim OS-level worker sandboxing or egress enforcement. The exact version pin `pnpm@12.16.1` is in the repository; explicit owner approval of version pins for production remains open.

## R1-G2 status — 2026-11-02

The mock execution path now uses an ephemeral Docker container, with actual-container negative tests run on the WSL2 development host. Tests demonstrated no-network behavior, filesystem and credential denial, no Docker socket, non-root identity, dropped capabilities, resource/time limits, cancellation, and scoped orphan cleanup. PostgreSQL, API/worker integration, SSE replay, and browser regressions passed locally. This is a local mock-only gate: the tested host uses a rootful Docker daemon, AppArmor and rootless/userns modes were unavailable, and remote CI has not run. No real model inference or runtime credential access was enabled. See [ADR-0008](adr/0008-container-isolated-mock-execution.md) and [R1-G2 evidence](evidence/R1_G2_SANDBOX_SECURITY.md).

## R1-G3 status — 2026-11-02

R1-G3 work adds pinned least-privilege CI, PostgreSQL custom-format backup and isolated restore verification, and hard worker/sandbox/database failure injection. Backup and restore were exercised locally with synthetic data, and the restored database served the existing API/worker integration smoke. Clean-clone verification and GitHub Actions passed on the public repository’s final revision; details are in [R1-G3 evidence](evidence/R1_G3_CI_RECOVERY.md). Shared Docker-daemon interruption remains unverified because unrelated services share it. A worker process may exit during a database outage; the recovery drill requires a replacement worker after PostgreSQL returns. Real AI runtimes remain disabled.

## Owner decisions still needed

- Approve the technology/version proposals before production use.
- Approve the authentication and token ownership model, including whether Omnis OS will register a Sign in with ChatGPT integration.
- Approve the real runtime and documented tool permissions after isolated proof.
- Review Claude Team/Agent SDK terms and any background use before enabling it.
- Review the committed package/image pins before any production deployment; pnpm 12.16.1 and the dependency lockfile now have a local reproducibility proof.
- Review [ADR-0007](adr/0007-loopback-mock-functional-gate.md) before any real runtime or non-loopback access is enabled.
- Review [ADR-0008](adr/0008-container-isolated-mock-execution.md) before extending the sandbox to arbitrary tools, enabling network access, or deploying outside the verified local environment. Obtain an independent Claude Code security/architecture review only after its background use and review procedure are approved; no Claude process or credentials were used for R1-G2.

## Post-audit remediation status — 2026-11-02

The audit base was `708d0f5e9b6083da852e26c0643c60c0f5879f85`. On local branch `security/post-audit-remediation`, M-1 workspace scoping, M-2 SSE sequencing, M-3 session bounds, M-4 authentication throttling, L-1 execution-generation fencing, M-6 mock-only Omnis authorization, L-4 ordered migration scaffolding, and M-7 safe backup snapshot policy have implementation and unit-level evidence. Sandbox security inspection tests now check Docker configuration, bind mounts, mountinfo, and a synthetic environment canary, with controlled fixtures that reject an extra mount or exposed canary.

Frozen dependency installation, formatting, ESLint, TypeScript, unit tests, and production build passed locally. Actual Docker and PostgreSQL suites were unavailable: Docker socket access was denied and `OMNIS_TEST_DATABASE_URL` was not configured. Consequently, database migration upgrade, lease fencing, restricted-role operation, backup/restore, browser sign-in/execution, and actual sandbox namespace behavior are not verified on this branch. M-5 least-privilege role separation remains confirmed and deferred. The worker still uses the Compose `omnis` account for runtime, migration, and pg-boss responsibilities. Worker restart supervision, durable authorization/audit, backup encryption, API pagination/backpressure, GitHub repository controls, and rootless or quota-backed sandboxing remain open.

Read-only GitHub API review found that `main` is not protected, there are no repository rulesets, Actions allow all actions, secret scanning and push protection are enabled, and Dependabot security updates plus non-provider secret scanning are disabled. No repository settings were changed. GitHub's response did not expose the plan-level eligibility of each control; see the remediation evidence for the exact scope and date of the review.

See [R1 post-audit remediation evidence](evidence/R1_POST_AUDIT_REMEDIATION.md) and [ADR-0009](adr/0009-runtime-authorization-and-credential-boundaries.md). This remediation does not authorize Hermes, Codex, or Claude inference.
