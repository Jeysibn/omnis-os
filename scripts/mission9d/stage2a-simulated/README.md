# Synthetic Stage 2A foundation

This directory is an isolated, test-only model. Its schemas require `synthetic-only` mode and `sim-*` authorization identifiers, which cannot satisfy a production authority contract. The synthetic ledger returns only `simulated_consumed`; it never starts work or emits a release permit. Stage 1 fixture records use the V3 snapshot fields: run, session, generation, manifest, attempt, path, ordinal, digest, receipt, boot and deadline, controller PID/start ticks, reservation BOOTTIME and journal-sequence digest. The fake adapter compares that tuple and rejects terminal, poisoned, missing and stale reservations. It does not read the live journal or implement the proposed lease amendment.

Production exclusion is checked through two layers: each workspace package build verifies its TypeScript entrypoint dependency graph; the web Rollup plugin checks included module IDs; Docker deployment trees and host application packaging are checked for the synthetic directory. The source graph guard fails if TypeScript is unavailable, an entrypoint/config is missing, an import cannot be resolved, or a non-literal dynamic import/require prevents resolution. Resolved third-party modules under `node_modules` are treated as external; unresolved bare specifiers, known workspace packages, `#` imports, and configured TypeScript aliases fail closed. Relative static assets that TypeScript cannot resolve are accepted only when the exact file exists; Vite then checks all emitted module IDs. Controlled tests exercise imports, re-exports, dynamic imports, aliases, indirect dependencies, external dependency classification and missing-artifact-evidence rejection. The authorized validation run exercised the actual compiler graph for all 11 production projects and the generated web artifacts; Docker image artifact checks remain pending for separately authorized hosted CI.

The store requires an explicit existing caller-owned directory with mode `0700`, and a ledger file owned by the current UID with mode `0600`. It uses same-directory temporary writes, file fsync, atomic rename and directory fsync. It validates corrupt/missing state fail-closed. A durable `pending` transition precedes `consumed`; recovery changes `pending` to `unknown`, which can never be consumed. Ambiguous commit poisons the instance. An acknowledgment lost after durable consumption yields no success result and duplicate requests cannot consume again. Revocation and consumption serialize in this process; a revocation committed first prevents consumption.

This implementation is **not** a production ledger. Serialization is process-local, not cross-process; `/tmp` test behavior does not establish WSL2 filesystem durability, power-loss safety, kernel lock semantics, or deadline enforcement. It must not be used across processes or imported into runtime code. The fake Stage 1 adapter cannot establish live Stage 1 liveness ordering. The fake adapter and simulated states do not prove real issuer authorization.

Release remains blocked pending a proven first-application-instruction deadline fence, independent supervision, and approved Stage 1 liveness semantics. There is no listener, endpoint, IPC socket, bootstrap, Docker/systemd integration, provider operation, or production registration in this directory.
